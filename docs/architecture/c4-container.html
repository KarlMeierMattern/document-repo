Document Repo — Containers (L2)

Deployable units and the protocols between them. The numbered flow (1–7) traces a single upload-and-extract journey; the cron + email flow is amber, auth is purple.

Upload journey (blue)

Browser asks Web for a presigned URL (creates a documents row in uploaded state), PUTs the file straight to R2, then asks Web to dispatch processing. Web flips status to processing and POSTs the processor — fire-and-forget with a 15 s timeout so Vercel doesn't block on Cloud Run.

Extraction (green)

Processor downloads the original from R2, normalises images (HEIC→JPEG, EXIF rotate, resize ≤1568 px), and runs the two-stage Claude pipeline. On success it writes document_fields + reminders and flips the doc to processed in one transaction.

Cron + email (amber)

Vercel registers the cron from vercel.json on production deploys only. The route auths via Authorization: Bearer CRON_SECRET, pulls reminders due ≤30 days, sends one digest, and bulk-updates them to status='sent'.

Auth (purple, dashed)

Auth.js + Google OAuth. The signIn callback rejects everything except OWNER_EMAIL, so the app is effectively single-user even though the OAuth provider is public.

Inter-service auth

Web → Processor: shared X-Processor-Secret header (rejected with 401 otherwise). Cron → Web: Bearer CRON_SECRET. R2 access keys never leave the two backend containers — the browser only ever sees short-lived presigned URLs.
