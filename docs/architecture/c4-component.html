Document Repo — Processor Components (L3)

Inside the FastAPI processor on Cloud Run. The orchestrator (main.py) drives a fixed pipeline; flow numbered 1–9. Sibling containers (Web App, R2, Anthropic, Neon) shown in their L2 fills.

Two-stage Claude pipeline

Step 6 actually fires two messages.create calls: a classifier first (returns doc_type), then the matched type's extractor with its tool schema (returns typed fields + reminders). Unknown classifier output falls back to generic.

Prompt caching

claude_client.py sets cache_control: ephemeral on both the system prompt and the tool definition. Repeated calls for the same doc type hit the cache, making re-runs ~10× cheaper / faster.

Image prep is conditional

PDFs (application/pdf) skip image_prep entirely and go to Claude as a document content block. Everything else is HEIC-decoded, EXIF-rotated, and resized to ≤1568 px before being sent as an image block.

Atomic writes

db.write_extraction wipes prior document_fields + reminders for the doc, inserts the new ones, and flips the documents row to processed — all in one transaction. On exception, the route flips status='failed' with a truncated error.

13 doc types

warranty, prescription, lab_result, insurance_card, invoice, receipt, vehicle_registration, vaccination_record, id_document, dna_report, medical_record, photo, generic. Each is its own module under extractors/ exporting NAME, SYSTEM_PROMPT, TOOL, transform().
